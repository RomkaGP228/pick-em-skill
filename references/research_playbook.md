# Как собирать данные и превращать их в рейтинги

## 1. Где брать данные

| Что | Где | Как |
|---|---|---|
| Состав стадии, посев, формат, результаты | Liquipedia (`liquipedia.net/counterstrike/...`), HLTV event page | WebSearch «<мейджор> stage N liquipedia» → WebFetch |
| Рейтинги | HLTV world ranking, Valve VRS (GitHub `ValveSoftware/counter-strike_regional_standings`), Liquipedia VRS | Свежий срез на неделю мейджора |
| Форма | HLTV results команды за 2–3 месяца, bo3.gg | Только LAN и топ-онлайн; смотри уровень соперников |
| Маппул | HLTV stats → team → maps (3 мес.), bo3.gg | Пики/баны, винрейт по картам, «пермабан» |
| Составы и замены | HLTV news, Liquipedia (roster), X аккаунты команд | Стенд-ины, смена капитана/тренера, визы, болезни |
| Мнения и pick'em инфлюенсеров | HLTV-предикты редакции, X (игроки, аналитики, кастеры), Reddit r/GlobalOffensive pick'em треды, YouTube/статьи с «pick'em predictions» | WebSearch «<мейджор> stage N pick'em predictions» + имена |
| Telegram | Публичные каналы читаются через `https://t.me/s/<channel>` | WebFetch страницы канала; это превью последних постов |
| Путь команды из прошлой стадии | Liquipedia таблица прошлой стадии | Баланс, Buchholz, кого обыграли, сколько Bo3 сыграли |

Пользователь может добавить свои любимые каналы и аккаунты в раздел «Мои источники» в конце этого файла — проверяй их каждый раз.

**Не используй** как источники букмекерские линии, коэффициенты, сайты скин-ставок и кейсов, промо-статьи «лучшие ставки на мейджор». Если статья с pick'em-прогнозом принадлежит такому сайту, бери из неё только фактуру (составы, результаты), а не рекламные вставки, и не ссылайся на промо.

## 2. Что проверить по каждой команде (чек-лист)
1. Рейтинг (VRS и HLTV) и тренд за последний месяц.
2. Последние 2–3 LAN-турнира: места, кого обыграли, кому проиграли.
3. Маппул: 2–3 сильные карты, пермабан, дыры. В Bo1 это решает больше рейтинга.
4. Состав: изменения после последнего турнира, стенд-ины, заявленный запасной (вспомни karrigan в Falcons в Кёльне).
5. Опыт мейджоров и big-stage: дебютанты чаще «горят» в решающих Bo3.
6. Путь в стадию (если не Stage 1): баланс в прошлой стадии, сила соперников (Buchholz), сколько Bo3 сыграли (разогрев vs усталость), не раскрыли ли они уже свои стратегии.
7. Логистика: часовой пояс и перелёт (Сингапур: +7 ч к Берлину в ноябре), буткемп в регионе, поддержка зала (в Сингапуре арена только на плей-офф).
8. Мотивация/контекст: «последний турнир состава», уход ключевого игрока после мейджора, слухи о распаде.
9. Pick'em-консенсус инфлюенсеров: кого массово ставят на 3-0 / 0-3.

## 3. Как превращать это в рейтинг для симулятора
Рейтинг — Elo на уровне одной карты (шкала 400). Разница → шанс выиграть карту:

| Разница | Карта | Bo3 |
|---|---|---|
| 0 | 50% | 50% |
| +50 | 57% | 61% |
| +100 | 64% | 71% |
| +150 | 70% | 79% |
| +200 | 76% | 86% |
| +300 | 85% | 94% |

В Bo1 симулятор дополнительно тянет шанс к 50/50 (`bo1_shrink` = 0.8).

**Автоматическая база — ранг VRS + `elo_adj`**: `python3 scripts/elo.py --date <дата старта> --fill stage.json`. Ранг переводится в рейтинг `1700 − 90·ln(rank)` (#1 = 1700, #8 ≈ 1513, #32 ≈ 1388), а `elo_adj` (только топ-20 VRS, −100…+100) добавляет свежую форму, в которой VRS запаздывает. Всё откалибровано на матчах мейджоров и 1 600 LAN-матчах топ-40 (`references/calibration.md`). Очки VRS напрямую не подставляй: они переоценивают фаворитов.

Ручные поправки `adj` — для того, чего **нет в результатах матчей** или что ещё не попало в данные VRS (они обновляются раз в неделю):

| Фактор | Типичная поправка |
|---|---|
| Стенд-ин / замена ключевого игрока прямо перед турниром | −30…−70 (и `"sd": 40`) |
| Новый капитан, < 1 мес. вместе | −20…−40 (и `"sd": 40`) |
| Свежая смена состава, уже сыграно 1–5 матчей | только `"sd": 40`, без сдвига: данные показывают неопределённость, а не падение силы |
| Громкий результат после последнего среза VRS (выиграли турнир на прошлой неделе) | +10…+30, с датой и турниром |
| Болезнь, визы, игрок не доехал | −20…−60 |
| Опыт и «big-stage» команды в решающих Bo3 | +5…+15 |
| Дебютант мейджора | −5…−15 |
| Неудобный часовой пояс без буткемпа | −5…−15 |
| Явный консенсус инфлюенсеров против модели | сдвинь на 10…20 в сторону консенсуса и проверь, почему |

**Форму за последние 2–3 месяца руками больше не добавляй**: её уже учитывает `elo_adj`, вторая поправка будет двойным счётом. Если ты не согласен с `elo_adj` (например, команда набила рейтинг на слабых турнирах), скажи об этом и поправь с причиной.

**Не давай поправок за «архетипы», которые уже объясняются рангом**: «квалифицированный из прошлой стадии», «3-0 в Stage 1», «инвайт против квалифицированного». Данные показали, что ранг их уже учитывает (`calibration.md`). Исторические паттерны из `major_history.md` используй только про конкретные составы и обстоятельства, которых нет в ранге.

Конкретные матчапы (сильная карта против дыры в маппуле, неудобный стиль, свежие очные встречи) задавай через `map_prob_overrides` — вероятность первой команды выиграть карту.

Правило честности: суммарная поправка одной команды больше ±80 требует очень веской причины (например, стенд-ин + новый капитан). Записывай каждую поправку в отчёт.

## 4. Проверка устойчивости
После основного прогона сделай 1–2 альтернативных прогона: (а) все ручные поправки ×0.5, (б) `"rating_sd": 50` — каждый прогон симуляции слегка сдвигает силу всех команд, как если бы рейтинги были неточными. Пик, который держится во всех прогонах, — «безопасный». Пик, который меняется, — пометь как рискованный и объясни, от чего он зависит.
