# Любой турнир CS2: как определить формат и чем его считать

Мейджор — частный случай. Для остальных турниров (IEM, BLAST, PGL, ESL Pro League, CCT и т. д.) формат собирается из нескольких «кубиков», и у каждого организатора свои правила. Поэтому формат **всегда берётся из источника турнира**, а не по памяти.

## 1. Где смотреть
- **Liquipedia**, страница турнира, разделы *Format* и *Participants*: стадии, Bo каждого матча, правила посева, кто куда приглашён. Если есть отдельные страницы стадий (`/Group_Stage`, `/Playoffs`), бери сетку оттуда.
- **HLTV**, страница события: участники, расписание, сыгранные матчи.
- Официальный сайт или рулбук организатора — если на Liquipedia формат описан неполно.
- Сам предиктор (Cybershoke, bo3.gg, HLTV и др.): **что именно нужно предсказывать и как начисляются очки**. Это определяет, что считать.

Перед расчётом коротко перескажи пользователю, как ты понял формат: «Группы — две GSL-четвёрки, все Bo3; плей-офф — single elimination на 6 команд, финал Bo5; на Cybershoke угадываем победителя каждого матча». Если что-то неясно — скажи об этом прямо.

## 2. Кубики формата и инструменты

| Формат | Как узнать | Инструмент |
|---|---|---|
| Swiss 16 команд, правила Valve (мейджоры и турниры, где организатор прямо ссылается на рулбук Valve) | 1v9 в первом раунде, Buchholz, решающие матчи Bo3 | `swiss_sim.py` (`pairing: valve`) |
| Swiss 16 команд, правила организатора | «Buchholz & initial seeds», иногда 1v16 в первом раунде, часто все Bo3 | `swiss_sim.py` с `pairing: high_low`, `round1: 1v16`, `format: all_bo3` — **приближённо**, предупреди пользователя |
| GSL-группа на 4 (openers 1v4, 2v3 → winners/elimination → decider) | «GSL», «double-elimination group of 4» | `bracket_sim.py --template gsl4` |
| Single elimination (4/8/16 команд) | «single-elimination bracket» | `bracket_sim.py --template single_elim` (или `playoffs_sim.py` для сетки мейджора) |
| Double elimination на 8 | upper/lower bracket | `bracket_sim.py --template double_elim8`; другие размеры — описать матчи вручную |
| Плей-офф с «байами» (часть команд стартует с полуфинала), групповая сетка нестандартного вида | Liquipedia, схема сетки | `bracket_sim.py` с вручную описанными матчами (`W:`/`L:` ссылки) |
| Круговой турнир / группы round robin | «round robin» | `predict.py` для каждого матча (симулятор не нужен, если предиктор просит победителей матчей) |
| Предиктор «угадай победителя каждого матча» | правила предиктора | `predict.py probs` для объявленных матчей |

Если стадия состоит из нескольких кубиков (две GSL-группы → плей-офф), считай их по очереди: сначала группы, затем плей-офф с учётом того, кто вероятнее выйдет. Для пиков «по ходу турнира» достаточно считать ближайшие объявленные матчи и обновлять прогноз после каждого игрового дня.

## 3. Посев, пары и тип турнира на не-мейджорных турнирах
- Во всех входных файлах ставь `"event_type": "other"` (до запуска `elo.py --fill`). На не-мейджорных турнирах фавориты выигрывают чуть реже, чем предсказывает модель, откалиброванная на мейджорах (проверено на 1 325 LAN-матчах топ-40): разница в силе сжимается на 10%. Кроме того, поправку `elo_adj` получают и команды №21–50 VRS (с половинным весом).
- Свежие матчи и заявки — как для мейджора (`--extra fresh.json`, `"roster"`). На турнирах вне мейджоров разрыв между данными VRS и стартом обычно больше, поэтому этот шаг здесь ещё важнее.
- Посев часто по VRS или рейтингу HLTV на дату, но **не всегда** — у организаторов бывают инвайты, квалификации, жеребьёвка. Бери посев со страницы турнира.
- Если в Swiss правила пар организатора неизвестны точно, симулятор даст приближение. На вероятности прохода это влияет слабо, на конкретные пары будущих раундов — сильно. Поэтому для пиков по матчам используй **реальные объявленные пары**, а не предсказанные (передавай их в `rounds` или в `predict.py`).
- Проверяй пары первого раунда: если `swiss_sim.py` строит другие, правило посева понято неверно.

## 4. Типы предикторов и что оптимизировать

| Предиктор | Что выбрать |
|---|---|
| Valve Pick'Em, Swiss-стадия (2×3-0, 6×проход, 2×0-3, нужно 5+) | `swiss_sim.py` — оптимизатор карточки под «5+» |
| Valve Pick'Em, плей-офф (согласованная сетка) | `playoffs_sim.py` |
| Победитель каждого матча, очки за угаданный | Самый вероятный победитель в каждом матче (`predict.py`). Почти монетки помечай честно |
| «Кто выйдет из группы / стадии» | Вероятности прохода из `swiss_sim.py` или `bracket_sim.py` |
| Предиктор с бонусом за сложный пик (андердог даёт больше очков) | Сравни ожидаемые очки: `шанс × очки`. Андердог выгоден, только если это произведение больше, чем у фаворита |
| Угадать счёт по картам (2:0 / 2:1) | Шанс карты `p` из `predict.py`: 2:0 = p², 2:1 = 2p²(1−p); для соперника аналогично |
| Чемпион турнира | Колонка «Champion» из `bracket_sim.py` / `playoffs_sim.py` |

## 5. Граница со ставками для сторонних сайтов
Сторонние предикторы бывают на сайтах, где рядом есть кейсы, рулетки и скин-беттинг. Работаем, только если сама игра в прогнозы бесплатная: никаких депозитов, взносов скинами или монетами, которые можно проиграть. Если для участия нужно что-то поставить — это ставка, и тут скилл не помогает. Скажи об этом одной фразой и предложи взгляд в терминах бесплатного Pick'Em. Не рекламируй и не упоминай без нужды прочие разделы таких сайтов.

## 6. Журнал прогнозов
Цель журнала — честно измерить, помогает ли исследование (поправки `adj`, `map_prob_overrides`) по сравнению с голым рангом VRS.
- Перед каждым игровым днём: `predict.py probs <вход> --log predictions.json`. Сохраняются обе вероятности: «только ранг» и «скилл».
- После матчей: `predict.py result predictions.json <id> <победитель>` (или попроси пользователя прислать результаты; можешь найти их сам на HLTV/Liquipedia).
- Итог: `predict.py score predictions.json` — точность, log-loss и Brier «ранг → скилл» по турнирам и в целом. Выводы — не раньше ~30 матчей, надёжно — от 60–100.
- **Где хранить:** в Claude Code или локально — файл в папке проекта. В claude.ai рабочая папка не переживает конец разговора: после каждого обновления отдай файл журнала пользователю и попроси приложить его в следующий раз.
- Не подгоняй поправки задним числом: прогноз фиксируется до матча, иначе тест бессмысленный.
